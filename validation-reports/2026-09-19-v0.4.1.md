# Validation report — nmsbonker v0.4.1

**Date**: 2026-09-19
**Spec**: none. A dependency bump, plus one feature adopted from what the bump
made available.
**Scope**: `fynedesygn` v0.1.4 → v0.1.28, twenty-four releases. The bump itself
needed no source change. One was then made deliberately: `internal/gui/app.go`
declares the navigation shapes this window allows.

---

## Summary

The bump is clean: the window builds, all sixteen test packages pass, and no
section, dialog, table, log pane or build step needed touching. Across
twenty-four library releases that is the result the library's additive
discipline is meant to produce, and it is worth recording that it did.

nmsbonker uses more of the library than the other two programs — `table`,
`logpane`, `forms` and `steps` as well as `shell`, `dialogs`, `widgets` and
`theme` — so it collects more of the fixes:

- **A result banner no longer takes every click in the window** (library
  0.1.13). A banner was a popup, a popup is an overlay, and Fyne routes pointer
  events to the top overlay rather than to the content, so for the six to twelve
  seconds a banner was up the first click anywhere went to dismissing it instead
  of to the control it was aimed at. Hover tips had the same defect (0.1.12).
- **A long log line wraps** (0.1.16 through 0.1.19). Longer than the pane it was
  drawn past the right edge and the remainder could not be read at all;
  continuation rows are now indented and marked. The pane also reflows when the
  window or the divider above it moves, where before it wrapped to whatever
  width it was first drawn at and stayed there.
- **A table no longer re-shapes its text on every resize** (0.1.27). Fyne
  re-shapes a label through harfbuzz whenever it is resized — for text that has
  not changed, only a width that has — and a table resizes every visible cell on
  every layout. A 300-row table now resizes in 27 microseconds where it took
  738; on a consumer's 7-column catalog this was 42% of the process's CPU during
  a window drag, with another 36% in the GC behind it.
- **A refused operation names what is holding the window** (0.1.20, 0.1.21)
  rather than saying "something is already running", and offers Cancel when that
  operation has one.

Appearance settings move from Fyne's preference store into a file the user can
read (0.1.10), with the old values read once, so a configured window opens the
way it was left.

**The navigation's shape is adopted** (library 0.1.10, spec 013): titles with
icons, icons alone, or hidden with the content taking the window, down the left
or along the top, with one control in the header and `Ctrl+B` to hide. Six lines
in `shellOptions`, because the library holds the control, the shortcut and the
storage; a program only declares what it allows.

Ten sections is what makes it worth having here: the icons-only shapes give the
content back the width the section list was taking. They are usable because
every section already had an icon —
`TestEverySectionHasAnIconForTheIconsOnlyShapes` pins that, since a section
added later without one would draw a generic picture to guess at.

## Tests

`go test ./...` — 16 packages, all pass. No existing test needed changing. Two
were added for the navigation shapes: one that the window offers all three modes
and both placements, one that every section has an icon.

The library's `fynetest.Walk` began descending `container.Split` in 0.1.26,
which can change the object count a structural walk sees. No test here asserted
such a count, so nothing broke.

## Code quality

`make lint` — 0 issues, pinned golangci-lint v2.12.2.
`go vet ./...` — clean.

## Security

`govulncheck ./...` — no vulnerabilities found.

The bump adds no new module to the graph and no new runtime dependency: Fyne
stays pinned at v2.8.1 and fynedesygn's only required dependency is Fyne.

## Release safety

Rollback is one line in `go.mod`, a `go mod tidy` and the removal of two fields
from `shellOptions`. No save-file format, no
archive handling and no on-disk layout changes with this release; the whole
change is confined to the window.

One migration worth stating: appearance preferences move to a settings file. The
old preference keys are read once when the file is absent, so a downgrade would
read the preference store again and find the values still there — the migration
copies rather than moves.

## Checks against the release procedure

- `VERSION`, the `**Version**` line in `README.md` and the newest changelog
  heading all read `0.4.1`. They did not agree before this release: `VERSION`
  said 0.4.0 and the README said 0.1.0, three releases of silence, which is why
  a check for it has been added to `.claude/CLAUDE.md`.
- The GUI builds with CGO and `-tags migrated_fynedo`, which the Makefile
  already carried.
