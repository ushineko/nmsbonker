## Summary

0.2.0 shipped a save editor that could unlock exosuit slots and set
currencies. This release makes it the editor the user asked for: faction
standing in the levels the game shows, read from the game's leveled stats
table; starships and the freighter, with slots up to the ceiling the game's
inventory table gives every craft (120 items, 60 technology), class, and type;
a browser over the raw JSON that edits one node at a time; and a Saves section
arranged as tabs so each part has the height. Every edit still goes through
spec 007's one guarded write path.

Two other things came from using the tool during the same days. A mod's
script can be edited from the Mods section, checked through the sandbox before
it is written. And when MBINCompiler v7.02.0-pre2 could not read GcUIGlobals
after the game updated, the build reported it as a missing game file: the
report, the Overview and the build banner now name a compiler failure as what
it is, and GcUIGlobals joined the compatibility probes, which now tell pre1 and
pre2 apart.

## Acceptance criteria

Every criterion of specs 008–011 is checked. The in-game ones were run by the
user on 2026-09-15 and reported "working"; the others by test or by a CLI run
against the real profile recorded in each spec's Status notes.

Measurements worth repeating:

- **Standing thresholds** (`metadata/gamestate/stats/leveledstatstable.mbin`):
  the same eleven levels for all six factions, at -5, -2, 0, 3, 8, 14, 21,
  30, 40, 60, 100; the nine from 0 up are the levels 1–9 the reputation
  screen shows. The user's Vy'keen 135 reads level 9, Gek 45 level 7.
- **Inventory ceiling** (`metadata/reality/tables/inventorytable.mbin`): every
  ship, freighter and exosuit size type carries Large bounds of 10×12 items and
  10×6 technology. The save's grid is the grid grown so far by purchases (an
  A-class fighter with 59 slots had grown to 10×6), so spec 007's
  "never grow the grid" rule was too conservative and was replaced.
- **Types** are the procedural scene files under
  `models/common/spacecraft/`; the seed is kept and the model path swapped.
- **Compiler failure**: pre2 on GcUIGlobals fails with "File not recognized";
  pre1 round-trips the same file byte for byte on the new game build.

## Phase 4 — Code quality

- Every new edit is a typed field on `save.ChangeSet` and goes through
  `save.Apply`, so the write path, the dry run and the GUI Preview did not
  change for any of them.
- The JSON writer no longer escapes `/`: the game's own saves carry model
  paths unescaped, which the earlier design note had wrong. Untouched strings
  were never affected; only strings the editor writes.
- Codex review was not rerun for this round; the write path it reviewed is
  unchanged and the new code sits above it.

---

## Phase 5 — Security review

**Verdict**: PASS

- `govulncheck` was run for 0.2.0 on the same dependency set; no module was
  added this release.
- All writes into the prefix still go through `core.writeSave` (backup, game
  check, atomic rename). `SetSaveNode` refuses the root and requires the path
  to exist, so a typo cannot add a key. `WriteModScript` writes only under
  the library directory, to a path taken from the reconciled build order,
  and keeps the previous text.
- No credentials, personal paths or Steam ids in the diff (grep over the
  changed files, excluding the specs' recon notes, which name none either).
