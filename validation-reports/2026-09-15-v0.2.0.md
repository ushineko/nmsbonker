## Summary

Until this release nmsbonker treated the game's save folder as untouchable:
save backup was a one-way copy and the README said "not a save editor". The
reason to change that was a limit no pak mod can reach. The exosuit's
one-slot-per-system purchase rule is enforced by the executable (tried and
recorded on 2026-09-12), but the unlocked slot count itself lives in the save,
and every established editor lifts it there. So does this one now, in Go, with
no Java, .NET or Python.

The format work was done against the user's own saves, read-only. Eighteen
files across four years of game versions decode, parse and serialise back byte
for byte; every manifest decrypts with the per-slot key, records the data
file's exact sizes, and re-encrypts to its own ciphertext. That last fact is
what forced the design: because the manifest carries the sizes, an edited save
needs its manifest rewritten, and a codec that could not reproduce the
manifest exactly could not be trusted to rewrite one.

The reversal of the old stance is bounded to one function. `core.writeSave`
copies the whole profile to the save backup first, every time; refuses while
`NMS.exe` is running unless told otherwise in words that say why that is
unsafe; writes the data file and then the manifest, each to a temporary name
and renamed into place; and touches nothing but the addressed pair. Everything
the editor does not change is written back as the game wrote it.

## Acceptance criteria

All eleven are checked in the spec; the ones with a measurement worth repeating:

**AC3 — fidelity on real saves.** Eighteen files, base versions 4142 to 4223,
Normal and Seasonal, Waypoint's flat layout and Omega's context split: decode,
parse, serialise, identical. The manifest timestamp equalled the data file's
mtime only for the newest pair (delta 0 s); older files differ by 1 s to 40
min, consistent with Steam Cloud downloads. The criterion was reworded to log
the delta, and the write path sets both mtimes to the manifest timestamp, which
is what the game does for files it writes itself.

**AC5 — the write, on a copy of the real profile.** Slot 9 manual, `save18.hg`:
units 162,810,044 → 162,810,045, checked against the original payload with one
literal substring replaced; then item slots 34 → 120. Decompressed 1,966,855 →
1,969,323 bytes, on disk 114,719 → 115,877; the manifest recorded both, the
file mode survived, `accountdata.hg` was untouched, the two writes left two
backups and the first held the original bytes. The user's own profile was not
written: its newest save still reports 114,719 bytes and its original mtime.

**AC6 — a running game.** With a fake `/proc` holding an `NMS.exe` entry the
write is refused and no backup is taken; with `Force` it proceeds, backs up and
marks the result. The criterion originally said a refusal should back up too;
it was reworded, since a refusal with a side effect is the worse behaviour.

**AC9 — parity.** Five new leaves (`saves slots|inspect|export|import|edit`),
five new GUI actions, no new allow-list entry.

**AC10 — in game.** The user ran the installed build against slot 9 and loaded
the game; reported as "basic functionality works" on 2026-09-15.

## Phase 4 — Code quality

**Names, never keys.** `internal/save/edits.go` addresses every field by its
readable name and resolves it through the mapping at the moment of use. No
obfuscated key is hard-coded in the editor, so a mapping that renames one is
followed and a mapping that lacks one fails with the name in the error rather
than editing the wrong field.

**One write path.** `EditSave` and `ImportSave` share `writeSave`; the backup,
the game check, the atomic rename and the manifest rewrite exist once.

**One place for the slot arithmetic.** File number, slot, kind and the cipher's
slot index are derived in `internal/save/profile.go` and nowhere else.

**The Overview's save dialog is gone.** Its listing moved into the Saves
section's Backups card; the Overview keeps its one-line summary and a button
that goes to the section.

**Cross-model review.** Codex reviewed the diff against the spec and returned
twelve findings; ten were fixed (export path canonicalisation, per-write backup
uniqueness, the version gate on imports, JSON grammar strictness, partial-write
reporting, offline mapping fetch, GUI draft preservation, the Tools card, an
independent oracle for AC5) and two were recorded as decisions in the spec.

## Phase 5 — Security review

**Verdict**: PASS

- **Dependency scan**: `govulncheck ./...` under `GOTOOLCHAIN=go1.26.0` (the
  toolchain the tool was built with) reports eighteen standard-library findings,
  each fixed in a go1.26 point release; the installed binaries are built with
  Go 1.27.1 and none applies to them. No finding names `pierrec/lz4/v4`, the one
  new dependency (pure Go, BSD-3).
- **The new write path into the user's world** is the subject of the release:
  backup first, game-not-running check, temp-file-and-rename per file with the
  original mode, data before manifest, only the addressed pair opened for
  writing (`accountdata.hg` and the other half of the slot are asserted
  untouched). A failure after the backup names the backup directory in the
  error.
- **Export cannot be aimed into the game.** Destinations are made absolute,
  resolved through symlinks along their longest existing prefix, and refused
  anywhere under the compatdata tree or the game directory. Tested with a
  direct path, a `..` spelling, a symlink into the profile and a path under
  `GAMEDATA`.
- **Import is gated.** A file has to parse as JSON with JSON's grammar (invalid
  escapes and non-JSON numbers are refused), carry a player state and be
  Waypoint or newer before anything is written.
- **Parsing untrusted files.** The JSON parser bounds nesting at 256 and
  validates chunk headers before allocating: a decompressed size outside
  1..0x80000 or a compressed size past the end of the file is an error, not an
  allocation.
- **Public-repository rules.** No save, no manifest, no mapping file and no
  personal identifier is committed. The golden tests read `NMSBONKER_SAVE_DIR`
  and `NMSBONKER_MAPPING_FILE` and skip without them; a grep of the diff for
  the Steam id, the user name and home paths comes back empty.
- **Secrets**: none. `GITHUB_TOKEN` is still read from the environment only.
- **Logging**: file names, sizes and the backup directory; never a save's
  contents.

## Phase 5.5 — Release safety

| Question | Answer |
| --- | --- |
| How is the code undone? | `git revert`, then rebuild. No persisted format changed; `config.json` and `report.json` are untouched by this release. |
| How is an edit undone? | Close the game, copy the `st_*` folder from the backup the result named back into the save folder. Every write takes its own backup; retention stays ten. |
| What about Steam Cloud? | The edit is uploaded on the next launch. If Steam shows a conflict, choose the local file; every write result says so. |
| Is anything deleted? | Save-backup retention deletes the eleventh-oldest backup on a successful write of a newer one and reports it. A session of many edits rotates older pre-deploy backups out, which the output makes visible. |
| What if the mapping is missing? | Listing still works from the manifests; inspect, edit, export with names and import refuse with the same instruction, `nmsbonker tools ensure`. `--no-network` reports the absence instead of downloading. |
| Migration? | None. An existing install gains the mapping on its next `tools ensure`. |

**Version bump**: `VERSION` 0.1.0 → 0.2.0, as asked. No tag.
